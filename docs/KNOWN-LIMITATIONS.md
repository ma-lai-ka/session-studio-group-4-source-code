# Delivery boundaries

- This is a **local source-code submission**, not a hosted service. A GitHub URL alone does not execute it. The copyable prompt needs local Codex with command access; it cannot bootstrap ChatGPT desktop from ordinary browser chat.
- First-time setup needs internet, Node/npm and Python. The setup agent can install prerequisites but may need human permission under operating-system or university policies.
- Gerd uses the user's own Codex ChatGPT authentication and allowance. Signing into the website's local test identity does not authenticate Codex. No subscription, credentials or model capacity are included in the repository.
- Native Codex v3 voice is experimental. The reference package is pinned and doctor probes actual support. Account access, future service changes, institutional firewalls and physical audio hardware remain external requirements. A successful voice list or WebRTC handshake is not proof of audible sustained conversation.
- The author reported working microphone/speaker conversation before packaging. This does not verify another computer. The final validation report distinguishes automated checks, local live checks and physical audio.
- Both the app and assistant run locally; Gerd requests send relevant planner/context/source content through the user's AI service. Private context, chat history and authentication are not committed or transferred with GitHub.
- Planning is a proposal requiring human review, not a guaranteed design outcome. Completed-work protections, scope checks, approvals and undo remain in place. Source inspection can take time and consume included AI allowance.
- Local board collaboration is scoped to this computer's database. Another computer does not receive boards/uploads or saved projects automatically. No hosted multiuser deployment is configured.
- `npm run build` verifies compilation. The supported full local experience uses `npm run start:local`; a production-only static or worker preview does not supply the local Gerd bridge.
- CI verifies supported operating systems without signing into an AI account. It cannot verify native mic/speaker operation or live subscription service availability. Do not describe CI as a physical voice test.
