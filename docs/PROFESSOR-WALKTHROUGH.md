# Test Session Studio

Use a disposable example while evaluating. The expected startup screen has no author projects. Gerd is the small assistant character; opening or hiding its chat does not itself request a new plan.

1. **Explore.** Choose Proceed and browse the method library. You may optionally import `examples/research-questions.json` using Import project / backup. It is clearly fictional, contains only preliminary sessions, and is never added automatically.
2. **Create a project.** For example: “Library study-space onboarding”; goal: “Use existing interview notes to frame actionable design questions.” Select Define, four bachelor students, 1.5 hours total and one session. Save using Create project & plan sessions.
3. **Watch automatic tailoring.** Until a tailored plan is accepted, each preliminary session contains only Introduction (5 min) and Closing (5 min); the rest is unplanned. Preliminary sessions cannot run as confirmed agendas. Gerd automatically starts clarifying the selected goal when connected.
4. **Confirm the brief.** Answer consequential questions and review the Facilitator brief. A possible fictional team is four bachelor design students; existing evidence is six interview summaries; access is existing notes only; meetings have four attendees; recruitment and fieldwork are out of scope. State whether there is an additional person-hour budget for analysis/preparation. Confirm only facts/assumptions you intend to use. The button shows progress and acknowledgement, then Gerd continues without another “continue” command.
5. **Review the proposal.** Gerd inspects Delft source pages and proposes a plan. It may take time depending on the account/model. Inspect session purposes, available time, activities and work outside sessions. Accept or Reject yourself. Rejection preserves the saved plan; acceptance has Undo. Different briefs may legitimately produce different plans; the example is not a prerecorded AI response.
6. **Test controls.** Check the activity indicator and collapsed Agent operations. Hide Gerd while it is working, then reopen it: hiding is not Stop. Reconnect and Microphone & voice are in the header. Mic mute pauses input; Stop cancels current work. Saved plans do not change without the required review.
7. **Test voice yourself.** In Microphone & voice select/check an input, allow browser microphone access and start a conversation. Speak, listen to a reply, interrupt it and request one planning change. Mute/unmute while Gerd works. Verify the proposal appears and remains pending until your acceptance. End voice in the settings when finished. Doctor only checks capabilities; it does not establish that your mic/speaker work.
8. **Edit and run.** Open a reviewed session plan and make a manual adjustment. Confirm only when satisfied. Start an eligible approved session. Create the project's workspace/board, upload a harmless test file, add a comment and test a method template. Finish a disposable session and inspect its completion record.
9. **Check persistence.** Reload using the same browser and port, export the project, then import a copy. Browser project JSON is a planning backup; it is not an archive of all uploaded board files. Preserve any important uploads separately.

If Gerd cannot connect, use the displayed recovery action and run doctor. An unavailable account/allowance or experimental voice transport is not a reason to edit application code or add paid API access. The manually editable planner can still be reviewed in an explicitly selected planner-only session.
